D B T project అంతా code కాబట్టి, Git లో store చేస్తాం.

Standard workflow ఏంటి అంటే…

First, main branch లో production-ready code ఉంటుంది.

Second, developer ఒక feature branch create చేసి, changes చేస్తాడు.

Third, pull request create చేస్తాడు. Team members code review చేస్తారు.

Fourth, C I check run అవుతుంది. ఇది మన changes ని automatic గా test చేస్తుంది.

Fifth, review and checks pass అయితే, code ని main లోకి merge చేస్తాం.

Sixth, production run ఈ main branch code ని use చేస్తుంది.

C I లో మన changed models and వాటి downstream models ని మాత్రమే build చేయడం Slim C I అంటారు. ఇది production artifacts తో compare చేస్తుంది.

C I కోసం separate schema use చేస్తాం. దీనివల్ల production data safe.

D B T Cloud లో C I built-in. D B T Core కి GitHub Actions లాంటి tools use చేయచ్చు.

ఒక Banking project example తీసుకుందాం.

మన.gitignore లో ఈ folders add చేస్తాం:

logs slash

ఇప్పుడు pull request మీద C I లో ఈ command run చేస్తాం:

D B T build dash dash select state colon modified plus dash dash defer dash dash state prod underscore artifacts dash dash target C I

ఈ command only changed models and వాటి downstream models ని build చేసి test చేస్తుంది.

Unchanged models ని production నుంచి refer చేస్తుంది.

ఏ test fail అయిన, pull request merge చేయకూడదు. అంతే! Production safe!

[confident] So, simple గా గుర్తుపెట్టుకోండి!

Git – Stores and versions the D B T project.

Pull request – Code review before merge.

C I – Automatically builds and tests the changes.

Slim C I – Builds only the changed models and their children.
