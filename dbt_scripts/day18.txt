[Explaining – Main Concept]

dbt lo idi Incremental Model tho possible.

First run lo incremental model motham table ni build chesthundhi.

Taruvatha runs lo only kotha or changed rows ni process chesi, existing table loki add chesthundhi.

Incremental model create cheyyadaniki config lo materialized incremental set chestham.

Mukhyamaina rendu concepts untayi.

First, is_incremental function. Idi table already undho ledho check chesthundhi. Incremental run ayithe true vasthundhi.

Second, this. Idi current model table ni refer chesthundhi.

Manam is_incremental block lo, existing table lo unna latest timestamp kanna kotha rows ni matrame select chestham.

unique_key set chesthe, dbt same key unna rows ni update chesthundhi. Duplicates avvavu.

Motham table ni malli build cheyyali ante, full-refresh option use chestham.

[Real-Time Project Example]

Oka Banking project example teesukundham.

models/marts/fct_transactions.sql lo:

{{ config(materialized='incremental', unique_key='TRANSACTION_ID') }}

SELECT
    TRANSACTION_ID,
    CUSTOMER_ID,
    TRANSACTION_AMOUNT,
    TRANSACTION_TS
FROM {{ ref('stg_transactions') }}

{% if is_incremental() %}
WHERE TRANSACTION_TS > (SELECT MAX(TRANSACTION_TS) FROM {{ this }})
{% endif %}

First dbt run lo motham data load avuthundhi. Taruvatha runs lo only kotha transactions process avuthayi.

Logic marchinappudu motham table rebuild cheyyalante:

dbt run --full-refresh --select fct_transactions

is_incremental – True when the model runs incrementally.

this – Refers to the existing model table.
