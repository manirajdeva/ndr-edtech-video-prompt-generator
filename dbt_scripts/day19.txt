[Explaining – Main Concept]

dbt lo idi Incremental Strategy tho control chestham.

Snowflake lo mainly moodu incremental strategies untayi.

First, merge!

Snowflake lo idi default strategy. Idi unique_key base chesukuni, matching rows ni update chesi, kotha rows ni insert chesthundhi.

Second, delete plus insert!

Idi matching rows ni first delete chesi, taruvatha kotha rows ni insert chesthundhi.

Third, append!

Idi kotha rows ni matrame add chesthundhi. Existing rows ni update cheyyadu. Logs and events lanti data kosam, ante marani data kosam idi baguntundhi.

Inko important setting on_schema_change. Source lo kotha column add ayithe em cheyyali ani idi decide chesthundhi.

ignore, fail, append_new_columns and sync_all_columns options untayi.

[Real-Time Project Example]

Oka Banking project example teesukundham.

Transactions ki status marutundhi. Anduke merge strategy use chestham:

{{ config(
    materialized='incremental',
    unique_key='TRANSACTION_ID',
    incremental_strategy='merge',
    on_schema_change='append_new_columns'
) }}

SELECT
    TRANSACTION_ID,
    CUSTOMER_ID,
    STATUS,
    TRANSACTION_AMOUNT,
    UPDATED_TS
FROM {{ ref('stg_transactions') }}

{% if is_incremental() %}
WHERE UPDATED_TS > (SELECT MAX(UPDATED_TS) FROM {{ this }})
{% endif %}

Ippudu PENDING transaction SUCCESS ayinappudu, same TRANSACTION_ID unna row update avuthundhi. Duplicate rows avvavu.

Audit log lanti ante marani data ayithe, append strategy use cheyyachu.

[Confident – Closing]

So, simple ga gurthupettukondi!

merge – Updates matching rows and inserts new rows.

delete plus insert – Deletes matching rows, then inserts.

append – Only adds new rows.

on_schema_change – Controls what happens when columns change.
