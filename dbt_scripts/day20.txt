[Explaining – Main Concept]

dbt lo idi Snapshots tho possible.

Snapshot ante source table lo rows ela marayo history ni track cheyyadam. Idi SCD Type 2 approach.

Snapshots ni snapshots folder lo define chestham.

Dheenilo mainly moodu settings untayi.

First, unique_key – row ni identify chese column.

Second, strategy – changes ela detect cheyyali. Timestamp strategy lo updated at column use chestham. Check strategy lo konni columns marayo check chestham.

Third, target schema – snapshot table create ayye schema.

dbt snapshot command run chesinappudu, change ayina rows ki kotha version add avuthundhi.

Snapshot table lo dbt valid from and dbt valid to columns untayi. Current row ki dbt valid to null untundhi.

[Real-Time Project Example]

Oka Banking project example teesukundham.

snapshots folder lo customer_snapshot.sql file create chestham:

{% snapshot customer_snapshot %}

{{ config(
    target_schema='SNAPSHOTS',
    unique_key='CUSTOMER_ID',
    strategy='check',
    check_cols=['CITY']
) }}

SELECT * FROM {{ source('bank_raw', 'customer') }}

{% endsnapshot %}

Ippudu snapshot run cheddham:

dbt snapshot

Customer CITY Hyderabad nunchi Bengaluru ki marinappudu, malli dbt snapshot run chesthe, two rows untayi.

Paata row ki valid to date untundhi. Kotha row ki valid to null untundhi.
