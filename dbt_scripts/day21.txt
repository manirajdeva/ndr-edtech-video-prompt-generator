[Explaining – Main Concept]

dbt lo idi Targets tho possible.

Target ante oka environment. Manam profiles.yml lo oke project ki dev and prod laanti multiple targets define chestham.

Prathi target ki separate schema, warehouse or role set cheyyachu.

By default, profiles.yml lo target value lo unna environment run avuthundhi. Prod run cheyyali ante, target option tho cheppali.

Inko useful concept Variables.

Variables ni dbt_project.yml lo define chesi, models lo var function tho use chestham. Command lo vars option tho values override cheyyachu.

Models lo target name check chesi, dev lo only konni rows process cheyyachu. Dheenivalla development fast ga, cheap ga untundhi.

Secrets ni env_var tho teesukovali.

[Real-Time Project Example]

Oka Banking project example teesukundham.

profiles.yml lo rendu targets define chestham:

bank_project:
  target: dev
  outputs:
    dev:
      type: snowflake
      schema: DBT_DEV
    prod:
      type: snowflake
      schema: ANALYTICS

Ee example lo account, user and warehouse details short ga skip chesam, kaani real file lo anni undali.

Production run kosam:

dbt run --target prod

Ippudu model lo dev data ni limit chestham:

SELECT * FROM {{ ref('stg_transactions') }}
{% if target.name == 'dev' %}
LIMIT 1000
{% endif %}

Variable kosam dbt_project.yml lo:

vars:
  start_date: '2026-01-01'

Model lo use cheyyadaniki:

WHERE TRANSACTION_DATE >= '{{ var('start_date') }}'
